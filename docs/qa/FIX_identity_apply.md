### The applier, rule by rule (contract section 6)
1. **Opening.** Overlays of the `ID-OPEN-*` / `ID-LABEL-*` family are removed from every unlocked shot; the style's own are put on the shot on screen at their nominal start (raking: opening 0 s, 9 s; label 6.2 s, 4.5 s; dim: opening 7 s, 5 s; the block's `nominal` numbers win), clamped to that shot. Under 3 s the start moves earlier inside the same shot; a shot under 3 s gets nothing and the report says `no_room`. Extension: the opening never sits on a card, it goes to the end of the shot before it. The words (title, artist, year) come from the old title card, else from what an earlier application wrote (so an owner's edit of the label survives and the same style twice stays identical), else from the project.
2. **Title slot.** The first `X-CARD-02` / `ID-BRAND-*` structure shot becomes the style's brand technique: slot `image` = the picture of the nearest earlier non-structure shot, camera = that shot's last key then a 3 % push; no usable camera (a layout, a diagram, no shot before) means the main picture whole with a 3 % push. `text` is the channel name from the block. A second title card is left alone (`extra_title`).
3. **Chapter cards.** Every `X-CARD-01`, `TXT-01` or `ID-MARK-*` structure shot becomes the style's mark. Title: the old title without its number, in title case, numbered "1. ...", "2. ...", in order (a locked card still counts). Picture and camera: the next non-structure shot's picture; the mark's LAST key is that shot's FIRST key (same numbers, copied), its first key is 4 % wider; without a camera, the main picture whole with a 3 % push. `dim` sets the entry transition from the block (clamped to the mark's length), `raking` clears it.
4. Id, start, intent, note and `locked` are kept. A locked shot is not changed and is listed. Shots whose picture or technique changed get `source: "identity"`.
5. The same style twice is byte-identical, raking then dim then raking equals raking once (both tested with `json.dumps` text equality).

`report` = `{"style", "changed": [shot ids], "skipped": [{"shot", "reason", "what", "message"}]}`. Reasons: `locked`, `no_title_slot`, `extra_title`, `no_title`, `too_short` (under `min_element_s`, 1.5 s: the card is left as it is), `no_room`, `no_time`. `what`: `open`, `label`, `brand`, `mark`.

## 2. The route, with a real request and answer

`GET /api/projects/{pid}/identity` returns `{style, default, options: [{id, label}]}`; `PUT` takes `{style, base_rev}` and returns `{rev, style, changed, skipped}`. `409` for a stale `base_rev` (body carries the current `rev`, nothing written), `422` for an unknown style (`code: identity_style_unknown`, `allowed`), a missing `style` or a missing `base_rev`; `404` for an unknown project or one without a storyboard (`GET` of a project without a storyboard answers `style: null`). Errors use the app's `ApiError`; Vietnamese sentences are in `errmsg.js`.

Real exchange against the test instance on the server (sample project `arnolfini`, record: `.scratch/idapply/route_example.txt`):

```
GET /api/projects/arnolfini/identity
{"style":null,"default":"raking","options":[{"id":"raking","label":"Vệt sáng quét"},{"id":"dim","label":"Tối lại, hiện tên"}]}

PUT /api/projects/arnolfini/identity
{"style":"dim","base_rev":"a00fca59543f1045c023bfcdaea4e6f7201a8926ace764d0e60cee86083b9e9e"}
-> 200
{"rev":"0c7f1185ec1afd3b0b0e6b9f8317f17a0e926ed4b9f3147f5de43b13e1b3a94a","style":"dim","changed":["s0001","s0009","s0010","s0019","s0033","s0045","s0057","s0066"],"skipped":[]}

PUT (stale base_rev) -> 409
{"detail":"base_rev does not match the saved revision","rev":"a00fca59543f1045c023bfcdaea4e6f7201a8926ace764d0e60cee86083b9e9e"}

PUT (unknown style) -> 422
{"detail":"unknown identity style 'sepia' (choose one of: raking, dim)","code":"identity_style_unknown","allowed":["raking","dim"]}
```
`s0001` is the first shot (opening overlays), `s0009` the title card, `s0010 ... s0066` the six chapter cards.

## 3. How undo works
- The route saves through the app's `commit` (validation, `SB.save`), under the project's storyboard lock, so the storyboard before the choice is copied to `history/` like for any save. A choice that changes nothing writes nothing (same revision, no new history file).
- Page: "Hoàn tác" next to the selector puts the storyboard back by a normal save of the content the page held before the choice (`PUT /storyboard` with the revision the choice returned). It is there after a choice that changed something, and goes when the owner saves or reloads (the revision is then another one). After it the selector says "Kiểu cũ" again (the storyboard has no `identity`). Tested in the browser: the revision after "Hoàn tác" equals the original revision.
- History: tested by restoring through the existing `POST /storyboard/restore` after damaging `storyboard.json`: the newest copy in `history/` is the storyboard before the choice (same revision, no `identity`).
- Edit by instruction is untouched: it does not re-apply the identity and its merge and undo rules were not edited. Its compile mode keeps the identity cards exactly (4 scopes, both styles, zero scope violations, identical shot lists).

## 6. Deviations from the contract (and why)
Each is a place where I did something other than, or more than, the contract says.
1. **Overlay `source` is `"agent"`, not `"identity"`.** Contract rule 4 says changed shots get `source: "identity"`; I do that for the shots the identity rewrites (title slot, chapter cards). The opening overlays carry `"agent"` (the compiler's word for "a program wrote it") and the first shot keeps its own `source` when it only received overlays. Reason: an edit by instruction that rebuilds a shot rebuilds its overlays with `source: "agent"` (`compile.build_overlay`); with `"identity"` the owner would be told "Chỉnh: mở đầu: vệt sáng quét" for a note-only edit (five tests of `tests/draft/test_edit_routes_e2e.py` showed it). For the same reason overlay starts are word anchors (the compiler's form), `dur` is in whole milliseconds, and the params of everything written are complete (registry defaults, passed as `defaults=` by the compiler and the route).
2. **`apply_identity` has one extra keyword, `defaults=`** (`StyleBundle.param_defaults`), and reads `meta["main_asset"]`. The contract signature is otherwise kept.
3. **`SOURCES` in `bti/engine/storyboard.py` gets `"identity"`** (beyond "the field and the two issues only"): without it each rewritten shot would carry an `unknown_source` warning.
4. **The words of the opening.** Contract: the old title card, else the project. I added a middle source: the opening overlays an earlier application wrote (either style; label line and small-capitals line convert into each other). Without it a second application of the same style was not byte-identical whenever the card's words differed from the project's (found by the route test on the demo project), and an owner's edit of the label was silently lost.
5. **The opening never sits on a card.** If the shot on screen at the nominal start is a structure shot (a title slot at 6 s in a short video), the overlay goes to the end of the shot before it. The contract says only "the shot on screen at the nominal start".
6. **Title case.** (Changed by the follow-up, item 5, which replaced the contract's list.) The small words are `a an the and or nor but for yet so of in on to at by as vs via per with from into`; one is capitalised when it is the first or the last word of the title or follows a colon ("The Borderland of Death: The Memorial Reading", "Two Readings: Marriage Certificate or Symbolic Union", "What Is It For").
7. **A card under 1.5 s is left as it is** (`too_short`), because the engine refuses an element shorter than `min_element_s`; the contract says only that the validation errors below 1.5 s.
8. **Compiler.** (a) `compile_specs(..., identity=True)` is a new keyword; `False` keeps the old cards (the existing tests that assert old cards need it, section 8). (b) In a draft, spec shots that use a title-slot or mark technique are ignored with the warning `card_written_by_agent` (the compiler places them, the briefing says so); in edit mode a copy of a saved identity card is carried through as a card and a new one (no `id`) is accepted as written. (c) `compile.py` first had its own `is_card` because `decompile.is_card` was not mine; after the follow-up (section 10) it just calls `decompile.is_card`.
9. **Files outside my list that I edited**: `bti/editor/static/js/sbissues.js` (two Vietnamese templates for the two new issue codes: `tests/editor_frontend/sbissues.test.mjs` fails for any code without one there, and `issueText` of the page reads them from there; the three route-error sentences are in `errmsg.js` as asked). `tests/e2e/stages/remote.mjs` only for the host name, as asked. Nothing else outside the list.
10. **Page extras.** The "Hoàn tác" button (a normal save of the previous content, section 3) is mine; the contract only says the usual history undo takes it back. `takeInTurn(turn, texts)` in `views/storyboard.js` got an optional second argument so the identity can reuse the prompt box's rule for server-side changes with its own sentences (`ok: ''` means no toast). The step-6 line sits under the table of the box "Sẽ làm ra" and is shown even when the plan is not ready, not as a row of the table.
11. **The style block** is read as the engine worker wrote it (`styles.<id>.{label_vi, open, label, brand, mark, mark_transition, nominal}`, `min_element_s`), with built-in nominal times (contract section 3) only for a role that has none and Vietnamese names only for a style that has no `label_vi`.

## 8. Needs another worker
(Items 1 to 4 were applied by me afterwards with the coordinator's permission, see section 10; they are kept here as the record of why.)
1. **`bti/draft/decompile.py`, function `is_card`** should also return True for a title slot or chapter mark of the identity (kind `base`, intent `structure`, technique in the style's `brand` or `mark` families); then `decompile`, `fastedit` (neighbours) and every test helper built on `is_card` treat them as cards, as they treat the old ones. Without it, five existing tests of `tests/draft/test_edit_routes_e2e.py` fail (`test_i`, `test_j`, `test_k`, `test_l`, `test_n`: the helper `content_ids` counts the marks as content shots: 7 instead of 6, 4 instead of 3, and the model is shown the marks as ordinary shots). The patch, verified in my private snapshot (it turns them green): `.scratch/idapply/proposed/bti/draft/decompile.py`:
   ```python
   def is_card(bundle, shot: dict) -> bool:
       sp = bundle.spec(shot.get("technique"))
       if sp and sp.get("kind") == "card":
           return True
       from bti.identity import read as read_identity
       cfg = read_identity(bundle.style)
       t = shot.get("technique")
       return bool(cfg) and shot.get("intent") == "structure" and (cfg.is_family(t, "brand") or cfg.is_family(t, "mark"))
   ```
   Everything I built works without it (compile has its own wrapper, edit mode is tested); it is what keeps the existing tests and the model's view of the storyboard clean.
2. **`tests/draft/test_compile.py`: eight tests assert the OLD cards** (the compiler now gives a new video its identity): `test_tiling_anchors_and_first_shot` (every shot `source == "agent"`), `test_chapter_card_sits_in_the_silence`, `test_title_card_only_when_the_silence_is_long`, `test_narration_on_screen_is_refused` (counts the overlays of the first shot), `test_locked_shots_pass_through_untouched_and_ids_are_kept` (with item 1 only the `identity=False` calls are needed), `test_cards_are_placed_from_the_lead_of_the_timing`, `test_title_lead_at_the_very_start_gives_a_title_card_first`, `test_a_locked_card_is_never_regenerated`. The fix is mechanical: add `identity=False` to every `compile_specs(...)` call of those tests. The patched file, verified (with item 1: `tests/draft/test_compile.py`, `test_edit_routes_e2e.py` and my compile tests, 68 passed): `.scratch/idapply/proposed/tests/draft/test_compile.py`. The same behaviours under the new look are tested in `tests/draft/test_identity_compile.py`.
3. **`bti/editor/static/js/camgeom.js`**, table `TARGETS`: add `'ID-BRAND-01'`, `'ID-BRAND-02'`, `'ID-MARK-01'`, `'ID-MARK-02'` with `{ camera: MATTE() }` (like `CAM-01`). Until then `tests/editor_frontend/camgeom.test.mjs` has two failing tests (258 of 260 pass); the engine worker reported the same.
4. `bti/editor/engine_stub.py` (`SOURCES`) does not know `identity`; only the stub engine's validation warns.
